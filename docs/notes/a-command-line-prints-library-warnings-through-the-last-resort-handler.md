A command with no log handler of its own prints every WARNING of a library to standard error, so the engine connector's log line, which holds the engine's error text, reached the terminal of `makna freshness refresh`.

Seen in WP-17 (2026-11-18, Python 3.13, psycopg 3, PostgreSQL 16.2). `PostgresConnector` logs `log.warning("%s", message)` with the scrubbed text of the driver's error, and when no handler is configured anywhere up the logger tree, Python's last-resort handler writes it to standard error. For a missing table that text is `relation "core.contract_monthly_snapshots" does not exist`; for a failed cast it can be a value of the data (`docs/notes/engine-error-text-can-carry-a-personal-value.md`). `makna.services.freshness.keep_engine_text_out_of_terminal()` adds a `NullHandler` to `makna.engine`, which ends the last-resort output; the command and the `init` step call it, and report only the measure's id and the error's class. Pytest installs a root log handler, so the effect cannot be seen in the test process: `tests/integration/test_freshness.py` runs the real connector in a fresh interpreter against a database without the tables, asserts that the text is printed without the handler (the premise), and that it is not printed with it. A configured root handler (the application's JSON log, a test's `caplog`) still receives the record, so a process that has one needs its own decision about that text.
